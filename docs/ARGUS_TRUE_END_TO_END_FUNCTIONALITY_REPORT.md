## 2. RUNTIME ARCHITECTURE

The ARGUS system operates under a single authoritative data pipeline driven exclusively by runtime telemetry generated by the Part 1 simulator and historical MIMIC-IV trajectories:

```
PART 1 SIMULATOR (Port 8001)
   │ (Synthetic Scenarios + MIMIC Replay Trajectories)
   ▼
PART 1 WEBSOCKET (`/api/v1/stream`)
   │
   ▼
PART 1 → PART 2 BRIDGE (`src/backend/services/part1_ws_bridge.py`)
   │ (Auto-reconnecting, event normalization, patient registration)
   ▼
PART 2 CDS INGESTION & FEATURE PIPELINE (`src/backend/services/`)
   │ (31 Canonical features, timestamp sliding windowing)
   ▼
ML INFERENCE & SHAP ENGINE
   │ (`logistic-regression-v1` Calibrated Risk + Linear SHAP)
   ▼
SMART ALERT ENGINE
   │ (Risk thresholds: RED >= 0.8, ORANGE >= 0.5, YELLOW >= 0.3, GREEN < 0.3)
   ▼
DATABASE PERSISTENCE
   │ (SQLite `argus.db` / PostgreSQL `PatientRecord`, `VitalRecord`, `PredictionRecord`, `AlertRecord`)
   ▼
PART 2 WEBSOCKET & REST API (Port 8000)
   │ (`/api/v1/stream`, `/api/v1/patients`, `/api/v1/patients/{id}/vitals`)
   ├───────────────────────────────┐
   ▼                               ▼
DESKTOP WEB APP (Port 5173)    ANDROID MOBILE APP (Infinix X6852 / ADB Port 8000)
   │ (React 18 + TS + Tailwind)       │ (Flutter + Local Notifications)
   ▼                               ▼
Live Dashboard / Focus / Ack    Live Telemetry, Alerts & Ack
```

## 11. SMART ALERT ENGINE & SEVERITY CLASSIFICATION

- **Threshold Policy**:
  - `CRITICAL` / `URGENT`: Risk $\ge 0.80$
  - `WARNING` / `REVIEW`: $0.50 \le \text{Risk} < 0.80$
  - `STABLE` / `WATCH`: $0.30 \le \text{Risk} < 0.50$
  - `LOW` / `STABLE`: Risk $< 0.30$
- **Hysteresis & Deduplication**: Prevents alert storming while creating a new `AlertRecord` with a distinct `alert_id` when clinical deterioration transitions risk bands.

## 12. ACKNOWLEDGEMENT & ALERT CONTINUITY (CRITICAL BUG FIX)

- **Previous Bug**: Mobile `app_state.dart` stored `patientId` in the `_acknowledgedAlerts` set, causing an acknowledged patient to be permanently muted for all future predictions and alerts.
- **Applied Fix**:
  1. Modified `AppState.acknowledgeAlert(alertId)` to store specific `alertId` in `_acknowledgedAlerts`.
  2. Updated `activeAlerts` filter to check `!_acknowledgedAlerts.contains(alert.alertId)`.
  3. Added `NotificationService.clearPatientNotification(patientId)` on acknowledgement so that when new deterioration occurs for `PATIENT-001`, a **NEW** `alert_id` (e.g. `alert-002`) is created and delivered with full sound, vibration, and notification banner.
  4. Telemetry streams continuously before, during, and after alert acknowledgement.
