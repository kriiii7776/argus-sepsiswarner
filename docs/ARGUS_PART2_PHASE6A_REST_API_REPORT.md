## 5. Validation Behaviour
- **Technical Validation:** Managed by Pydantic V2 / FastAPI. Missing required fields (`patient_id`, `timestamp`), invalid types, or malformed datetimes automatically return `422 Unprocessable Entity`.
- **Null Safety in Feature Extraction:** Optional vital sign fields (e.g. `map`, `lactate`) default to `None`. Added explicit `None` guards in `src/backend/services/inference_runtime.py` to prevent `TypeError` during numpy/math operations.
- **Clinical Boundaries:** Standard bounds are maintained without inventing arbitrary clinical rules.

---

## 6. Error Handling
- **HTTPExceptions:** Raised explicitly with clean error details (`404 Not Found` for invalid patients, `400 Bad Request` for invalid input parameters).
- **Exception Isolation:** Ingestion router re-raises `HTTPException` cleanly to avoid masking client errors as `422` or `500`.
- **Security:** Stack traces, internal file paths, model artifact paths, and secrets are strictly suppressed from API responses.

---

## 7. Status Codes
- `200 OK`: Successful read operations (`/health`, `/model-version`, patient queries).
- `201 Created`: Successful event ingestion and risk prediction (`/events/vitals`).
- `400 Bad Request`: Invalid client request parameters.
- `401 Unauthorized`: Missing or invalid Bearer token on protected routes (`/patients/...`).
- `404 Not Found`: Non-existent patient resource.
- `422 Unprocessable Entity`: FastAPI/Pydantic validation failure (missing mandatory fields or invalid datetimes).
- `500 Internal Server Error`: Reserved for unhandled internal failures.
